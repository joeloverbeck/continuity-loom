# Approval checkpoint — PRD #200 (scene beat annotations) → 3 child slices

Nothing is staged, validated, or published. No tracker mutation has happened and none will until you
explicitly authorize this proposal. I expect to iterate on this before any write.

## Story ordinals

PRD #200's user stories are unnumbered in the body, so this checkpoint assigns temporary ordinals in
body order. Confirm the mapping (or correct it) before publication:

- **US1** — as an author, I can attach scene beat annotations to a scene so my intent for a beat is
  recorded as author-entered record data.
- **US2** — as an author, my scene beat annotations shape the prose prompt deterministically, so
  generation follows the beats I set.
- **US3** — as an author, I can add, revise, and remove those annotations where I already work on the
  scene, without leaving my writing flow.

## Proposed family

1. **Title**: Store scene beat annotations on the story record
   - **Blocked by**: none — can start immediately
   - **User stories covered**: US1
   - **Scope**: the stored shape and its validation, end to end — schema field in `@loom/core`,
     validation behavior, persistence in `@loom/server`, and the matching update to
     `docs/specs/story-record-schema.md`. No UI; the browser boundary is asserted unchanged.
   - **Test seam**: `@loom/core` schema/validation unit tests plus a server persistence round-trip
     (write → reload → identical annotations), and a load of a project saved without the field.
   - **Acceptance criteria (frozen count: 4)**: (1) annotation field accepted and validated on the
     scene record; (2) annotations survive a save/reload round-trip unchanged; (3) a project stored
     before this slice loads unchanged with no annotations and no shim or alias path; (4)
     `docs/specs/story-record-schema.md` describes the field as the authority for its shape.

2. **Title**: Compile scene beat annotations into the prose prompt
   - **Blocked by**: "Store scene beat annotations on the story record" (this family) and **#188**
     (pre-existing tracker prerequisite)
   - **User stories covered**: US2
   - **Scope**: deterministic compilation of stored annotations into the prose prompt in
     `@loom/core`, plus the matching update to `docs/specs/compiler-contract.md`. No UI and no
     provider call; the preview surface itself is untouched.
   - **Test seam**: golden compiler tests — one asserting the emitted block and its fixed ordering,
     one asserting byte-identical output to today when a scene has no annotations.
   - **Acceptance criteria (frozen count: 3)**: (1) annotations compile into a dedicated block in a
     fixed, record-derived order; (2) a scene with no annotations produces output byte-identical to
     the current compiler; (3) `docs/specs/compiler-contract.md` documents the block as part of the
     deterministic contract, covered by a golden test.

3. **Title**: Edit scene beat annotations in the scene editor
   - **Blocked by**: "Compile scene beat annotations into the prose prompt" (this family). #188 is
     transitive through the compiler slice and is deliberately not re-listed here.
   - **User stories covered**: US3 (and completes the authoring path for US1)
   - **Scope**: the only browser-visible slice — add/revise/remove annotations in the existing scene
     editor in `@loom/web`, prompt-preview freshness after an edit, and the `docs/user-guide.md`
     update. No new route and no provider call.
   - **Test seam**: component/browser scenario over the scene editor covering keyboard operation and
     accessible names, plus a preview-freshness assertion after an annotation edit.
   - **Acceptance criteria (frozen count: 8)**: the eight criteria mapped one-to-one to the canonical
     browser-visible checklist in the table below.

**Prefactoring verdict**: no prefactor slice. The record slice already lands the storage seam that
the compiler and editor consume, so an earlier refactor would neither leave a distinct coherent
verified state nor materially simplify later work — it would only split one migration into a
half-migrated intermediate. The three slices are the smallest complete family; one fewer would force
a schema-plus-compiler slice with no independently reviewable behavior.
